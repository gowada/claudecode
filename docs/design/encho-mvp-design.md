## 4. UX設計思想まとめ

### 4.1 設計原則

#### 「残すこと」を最優先

```
正確さ < 記録すること

酔っていても、時間がなくても、
とにかく「残す」ことができれば成功。
詳細は後から埋められる。
```

**具体的な施策：**
- 必須入力は「名前」のみ
- 写真・メモ・詳細はすべてスキップ可能
- 音声入力を全面的にサポート
- 日時・場所は自動取得でユーザー負担を最小化

#### 1画面＝1アクション

```
迷わない。考えさせない。
画面を見れば、次に何をすべきかわかる。
```

**具体的な施策：**
- 新規作成はステップ形式で1項目ずつ
- 各画面に明確な主アクションを1つだけ配置
- 「戻る」「次へ」以外の選択肢を極力排除

#### 写真が記憶を呼び戻す

```
テキストより写真。
顔を見れば、声を聞けば、
その日のことを思い出せる。
```

**具体的な施策：**
- 新規作成の最初のステップは写真
- 一覧画面は写真中心のカードUI
- 詳細画面は写真ヘッダーで大きく表示

### 4.2 情報設計のポイント

#### 「管理」ではなく「記録」

```
このアプリは「人脈管理ツール」ではない。
「縁を大切にする帳面」である。
```

**言葉選びの指針：**
- × 登録する → ○ 残す、記す
- × 連絡先 → ○ 縁
- × データ → ○ 記録
- × ユーザー → ○ あなた
- × 追加 → ○ 記す

#### 時間軸で縁を育てる

```
出会い → 再会 → また再会...
縁は点ではなく、線として続いていく。
```

**具体的な施策：**
- 「再会」という概念を明示的に設計
- 詳細画面で時系列の履歴を表示
- 「最終更新日」を一覧に表示（活きている縁がわかる）

### 4.3 UIトーンガイド

#### ビジュアルトーン

| 要素 | 方針 |
|:-----|:-----|
| 配色 | 落ち着いた和モダン（墨色、生成り、藍） |
| フォント | 明朝系をアクセントに、本文はゴシック |
| 余白 | 十分な余白で情報を詰め込みすぎない |
| アイコン | シンプルな線画スタイル |
| 写真 | 角丸、柔らかいシャドウ |

#### 参考カラーパレット

```

Secondary:  #8B7355（煤竹色）  - サブアクション、アイコン
Background: #F7F5F0（生成り）  - 背景基調
Surface:    #FFFFFF（白）      - カード、入力欄
Text:       #333333（墨）      - 本文
TextSub:    #888888（鼠色）    - 補足テキスト
Accent:     #C84C4C（緋色）    - 通知、警告
```

#### 文言トーン

| カテゴリ | 例 |
|:---------|:---|
| 動作 | 「残す」「記す」「たどる」 |
| 関係性 | 「縁」「ご紹介」「再会」 |
| 時間 | 「はじめて会った日」「再会の記録」 |
| 励まし | 「大丈夫です」「思い出せる形で」 |

### 4.4 アクセシビリティ配慮

```
年齢を重ねても使えるデザイン
```

**具体的な施策：**
- 十分なフォントサイズ（本文16pt以上）
- コントラスト比の確保
- タップ領域は44pt以上
- 音声入力の全面サポート
- シンプルな画面遷移

### 4.5 将来拡張への備え

#### データ設計の拡張性

```typescript
// 現在のMVP
Person {
  introduced_by: PersonId | null  // 1人の紹介者
}

// 将来の拡張
Person {
  connections: Connection[]  // 複数の関係性
}

Connection {
  person_id: PersonId
  type: 'introduced_by' | 'colleague' | 'friend' | ...
  since: Date
}
```

#### 機能拡張の優先度

| 優先度 | 機能 | 備考 |
|:------:|:-----|:-----|
| 高 | SNSリンク | Instagram / X / LINE |
| 高 | タグ管理 | 分類・検索の強化 |
| 中 | ネットワーク可視化 | 紹介の連鎖を図示 |
| 中 | 月次振り返り | プッシュ通知との連携 |
| 低 | Evernoteインポート | 既存ユーザー向け |

## 5. データモデル詳細

### Entity: Person（縁）

```typescript
interface Person {
  id: string;                    // UUID
  name: string;                  // 名前（必須）
  photos: Photo[];               // 写真（0-3枚）
  first_met_at: Date;            // 初めて会った日時
  first_met_place: string;       // 初めて会った場所
  first_met_location?: GeoPoint; // 緯度経度（任意）
  situation: Situation;          // シチュエーション
  memo: string;                  // メモ
  introduced_by?: string;        // 紹介者のPersonId
  created_at: Date;              // 作成日時
  updated_at: Date;              // 更新日時
}

interface Photo {
  id: string;
  uri: string;
  taken_at?: Date;
}

type Situation =
  | 'bar'       // 飲み屋
  | 'work'      // 仕事
  | 'referral'  // 紹介
  | 'event'     // イベント
  | 'other';    // その他

interface GeoPoint {
  latitude: number;
  longitude: number;
}
```

### Entity: MeetLog（再会ログ）

```typescript
interface MeetLog {
  id: string;              // UUID
  person_id: string;       // 紐づくPersonのID
  met_at: Date;            // 再会日時
  place: string;           // 場所
  location?: GeoPoint;     // 緯度経度（任意）
  memo: string;            // メモ
  photos: Photo[];         // 写真（0-3枚）
  created_at: Date;        // 作成日時
}
```

### インデックス設計

```
Person:
  - PRIMARY KEY (id)
  - INDEX (updated_at DESC)      -- 一覧の並び順
  - INDEX (name)                 -- 名前検索
  - INDEX (introduced_by)        -- 紹介者からの逆引き

MeetLog:
  - PRIMARY KEY (id)
  - INDEX (person_id, met_at DESC)  -- 人ごとの時系列表示
```

## 6. 実装優先度

### Phase 1: Core MVP（最優先）

1. **縁の新規作成**（最重要）
   - 写真撮影/選択
   - 名前入力（音声対応）
   - GPS自動取得
   - 保存

2. **縁一覧表示**
   - カード型UI
   - 更新順ソート

3. **縁詳細表示**
   - 基本情報表示
   - 写真表示

### Phase 2: 再会機能

4. **再会記録**
   - 再会ログ追加
   - 履歴表示

5. **編集機能**
   - 既存情報の編集
   - 写真追加/削除

### Phase 3: 関係性

6. **紹介者設定**
   - 既存の縁から選択
   - 詳細画面で表示

7. **検索・フィルタ**
   - 名前検索
   - 場所検索
